# ProjectScale Fiverr Publication Checklist

Purpose: reduce the remaining Fiverr launch work to owner-authenticated actions only. Use with `fiverr-gig-launch-kit.md` and `fiverr-gallery-asset-spec.md`.

## Current Fiverr publication facts — rechecked August 16, 2026

- Gig creation/editing is desktop-only.
- New freelancers may have up to 4 active Gigs, but Fiverr recommends focusing on one initial Gig.
- Fiverr pre-fills `I will...`; keep the service title clear and avoid special characters such as `&`, `/`, `"`, and `+`.
- Use all 5 relevant search tags.
- Fiverr supports up to 3 packages, but the live category may impose higher minimums or standardized fields.
- Current Create-a-Gig guidance requires at least one revision option per package. Set the smallest truthful revision allowance the live UI accepts; do not imply revisions can expand purchased scope.
- Description limit: 1,200 characters. Up to 10 FAQs may be added.
- At least 1 Gig image is required; up to 3 are allowed. Recommended image size is 1280×769 px at 72 DPI. Keep image text to 10 words or fewer and use only owned/authorized media.
- Up to 2 optional portfolio PDFs may be added; only the first 3 pages of each are displayed.
- Before publication Fiverr may require display name, email, phone, personal/business verification, and applicable tax information (including W-9 for U.S. freelancers).
- Do not put off-platform contact information or Stripe/direct-checkout links in the Fiverr Gig. Fiverr permits portfolio/website links to demonstrate experience, but business generated on Fiverr must remain within Fiverr's permitted transaction/communication flow.
- Responsible AI assistance remains permitted when customized, meaningfully refined, lawful, and freelancer-accountable.

## Owner-controlled gate

Do these personally in the authenticated Fiverr seller account. Do not delegate identity verification, CAPTCHA, tax attestations, phone verification, or facts about the account owner.

- [ ] Sign in to the intended Fiverr seller account on desktop.
- [ ] Complete any required seller onboarding, display-name/email, phone/personal/business verification, tax forms, or identity checks truthfully.
- [ ] Open **My Business → Gigs → Create a New Gig**.
- [ ] Select the closest currently available Data Cleaning / Data Processing category shown by Fiverr. Do not force a category that is not offered in the current UI; category cannot normally be changed after publication.

## Copy-ready Gig fields

**Title:** I will clean validate and normalize your CSV or Excel data

**Suggested search tags:**
- data cleaning
- csv cleaning
- excel cleaning
- data validation
- data formatting

Use the full description, FAQ, buyer requirements, and package scope from `fiverr-gig-launch-kit.md`. Keep the final Fiverr description at or below the live 1,200-character limit.

### Intended package ladder

**Basic — Clean Start — $15**
- 1 CSV/XLSX
- up to 1,000 data rows
- bounded cleanup/formatting under supplied rules
- explicit-rule duplicate handling
- change/exception summary
- source preserved

**Standard — Clean + Validate — $45**
- 1 CSV/XLSX
- up to 5,000 data rows
- cleanup + normalization + rule-based validation
- duplicate handling
- documented import/report-ready preparation when supplied
- change/exception summary
- source preserved

**Premium — Reusable Workflow — $95**
- 1 supported CSV/XLSX workflow
- up to 7,000 data rows for included demonstration run
- cleanup + normalization + validation rules
- reusable Python workflow when suitable for deterministic automation
- usage notes + change/exception summary
- source preserved

For each package, choose a realistic delivery time and the smallest truthful revision count Fiverr currently accepts. A revision corrects work within purchased scope; it does not add files, rows, new rules, or a new workflow.

If Fiverr's current category UI imposes standardized package fields, minimums, or other mandatory settings that conflict with these intended fields, obey the live Fiverr UI and preserve the commercial intent as closely as possible without making unsupported promises.

## Buyer requirements to enable

Require the buyer to provide:
- source file covered by package;
- desired result;
- required column names / formatting / duplicate rules;
- fields that must remain unchanged;
- documented destination field specification for import-ready work;
- confirmation they are authorized to provide the data;
- advance notice if a non-AI workflow is required.

## Immediately after publication

Record these in the Factory execution issue / cash ledger:
- publication date;
- public Fiverr Gig URL;
- exact live package prices/scopes if Fiverr required changes;
- any platform fees that can be verified from the account;
- zero revenue until an actual completed paid transaction is observed.

Then distribute the public Gig/catalog only through channels whose current rules explicitly permit commercial/For-Hire promotion. Do not mass-message Fiverr buyers, automate unsolicited DMs, manufacture Reddit account eligibility, or spam communities.

## Fulfillment rule

Every paid order remains freelancer-accountable. Preserve the source, apply explicit reviewable rules, flag ambiguity instead of inventing facts, review the output before delivery, and keep actual transaction revenue separate from leads/views/hypothetical gains.
