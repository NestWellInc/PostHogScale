# ProjectScale Buyer Response + Upsell Kit

Purpose: convert legitimate inbound interest into clearly scoped paid work while protecting the $15–$25 starter offers from scope creep and routing repeat needs toward higher-value/recurring services.

## Core rule

Do not promise work before scope is known. Do not expand a starter checkout to cover larger/multi-file/automation work for free. Only completed paid transactions count as revenue.

## First response to a qualified inquiry

Thanks for reaching out. I can help with clearly scoped CSV, Excel, spreadsheet, or PDF-table work.

To point you to the right option, please send:
- file type(s)
- approximate rows/files/pages
- the exact result you want
- any columns, formulas, formats, or matching keys that must be preserved
- whether this is one-time or recurring work

Please do not send passwords, API keys, card data, credentials, or data you are not authorized to provide.

AI-assisted tools may be used where appropriate, with the result reviewed against the agreed scope before delivery.

## Scope-creep response

That request goes beyond the starter scope because it adds [multiple files / reusable automation / dashboard work / extensive validation / additional transformation rules]. I can still handle it, but it should be scoped separately rather than folded into the entry checkout. If you send the approximate file count/size and required output, I can route it to the appropriate larger-work tier.

## Recurring-work response

Since this is likely to repeat, there are two sensible structures: a reusable workflow that reduces repeated manual processing, or ongoing maintenance if the rules/files continue to change. I would first confirm the recurring inputs and exact output rules so the solution stays bounded and reviewable.

## Reusable PDF extraction response

If these PDFs use the same or a small number of stable layouts, a reusable extraction workflow may make more sense than paying for repeated one-off conversions. It can be scoped around the specific fields/tables you need and the layouts you are authorized to process. I would need representative files and the required output schema before quoting it.

## Authorized automation boundary

Accept automation only when the buyer is authorized to access/process the source and the workflow does not require bypassing CAPTCHAs, anti-bot controls, access restrictions, identity checks, qualification tests, or platform rules. Do not accept credential harvesting, spam, impersonation, unauthorized scraping, or prohibited automation.

## Payment + fulfillment rule

For direct sales, match the completed Stripe payment to the purchaser before fulfillment. Do not treat an email, uploaded file, verbal promise, lead, cart, or prospective contract as verified revenue.

Record:
- gross payment
- actual platform/processor fee when available (estimate only when clearly labeled)
- approved direct cost
- verified net cash
- evidence/reference

## Post-delivery expansion check

After successful delivery, ask only when relevant:
1. Does this same cleanup/conversion happen repeatedly?
2. Are there additional files that follow the same rules?
3. Does the buyer need an import-ready/report-ready output?
4. Would a reusable workflow remove repeated manual work?
5. Is ongoing maintenance genuinely useful?

Use the answers to route upward; never manufacture urgency or unsupported savings claims.
